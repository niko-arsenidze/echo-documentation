The Users API lets you manage every member of your Google Platform workspace without touching the dashboard. Use it to automate onboarding flows, synchronize user directories, audit account roles, and provision accounts from external identity providers. All Users endpoints are scoped under `/v1/users` and require a key with at least `read` scope for GET operations or `write` scope for POST operations.

---

## User Object

Every endpoint that returns a user (or a collection of users) includes the following fields:

<ResponseField name="id" type="string">
  Unique identifier for the user (UUID format).
</ResponseField>

<ResponseField name="email" type="string">
  The user's primary email address.
</ResponseField>

<ResponseField name="name" type="string">
  The user's display name.
</ResponseField>

<ResponseField name="role" type="string">
  The user's workspace role. One of `admin`, `member`, or `viewer`.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the account was created (e.g., `2024-03-15T10:30:00Z`).
</ResponseField>

<ResponseField name="avatar_url" type="string">
  Public URL of the user's avatar image, or `null` if none is set.
</ResponseField>

## GET /users

List all users in the workspace. Results are paginated and can be filtered by role.

```bash
curl -H "Authorization: Bearer YOUR_API_KEY" \
  "https://api.your-domain.com/v1/users?page=1&per_page=20&role=admin"
```

### Query Parameters

<ParamField query="page" type="integer">
  Page number to retrieve. Defaults to `1`.
</ParamField>

<ParamField query="per_page" type="integer">
  Number of users per page. Defaults to `20`, maximum `100`.
</ParamField>

<ParamField query="role" type="string">
  Filter results to users with a specific role. Accepted values: `admin`, `member`, `viewer`.
</ParamField>

### Response

Returns a paginated `data` array of user objects and a `meta` object.

```json
{
  "data": [
    {
      "id": "usr_01hx3k9p2bnf7qw8r",
      "email": "alex@example.com",
      "name": "Alex Rivera",
      "role": "admin",
      "created_at": "2024-01-10T09:00:00Z",
      "avatar_url": "https://cdn.your-domain.com/avatars/alex.png"
    }
  ],
  "meta": { "page": 1, "per_page": 20, "total": 42 }
}
```

## GET /users/{id}

Retrieve a single user by their unique ID.

```bash
curl -H "Authorization: Bearer YOUR_API_KEY" \
  https://api.your-domain.com/v1/users/usr_01hx3k9p2bnf7qw8r
```

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the user to retrieve.
</ParamField>

### Response

Returns a single user object inside `data`.

```json
{
  "data": {
    "id": "usr_01hx3k9p2bnf7qw8r",
    "email": "alex@example.com",
    "name": "Alex Rivera",
    "role": "admin",
    "created_at": "2024-01-10T09:00:00Z",
    "avatar_url": "https://cdn.your-domain.com/avatars/alex.png"
  },
  "meta": {}
}
```

## POST /users

Create a new user and add them to your workspace. The new user receives an invitation email to set their password.

```bash
curl -X POST \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"email": "jordan@example.com", "name": "Jordan Kim", "role": "member"}' \
  https://api.your-domain.com/v1/users
```

### Body Parameters

<ParamField body="email" type="string" required>
  The email address for the new account. Must be unique within the workspace.
</ParamField>

<ParamField body="name" type="string" required>
  The display name for the new user.
</ParamField>

<ParamField body="role" type="string">
  The workspace role to assign. One of `admin`, `member`, or `viewer`. Defaults to `member` if omitted.
</ParamField>

### Response

Returns the newly created user object with HTTP `201 Created`.

```json
{
  "data": {
    "id": "usr_02jy4m0q3cog8rx9s",
    "email": "jordan@example.com",
    "name": "Jordan Kim",
    "role": "member",
    "created_at": "2024-06-01T14:22:00Z",
    "avatar_url": null
  },
  "meta": {}
}
```
